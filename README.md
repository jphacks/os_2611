# Work Intake

### AIは使っている。でも、自分の仕事にどう活かせばいい？

**Work Intake** は、ユーザーの仕事・学習環境を理解し、普段使っているAIを実際の作業に活かすためのオープンソースSkillです。

AI初心者にとって難しいのは、AIとの会話そのものよりも「自分の作業のどこに使えるか」「何を準備すべきか」「どのツールが必要か」を判断することです。Work Intake は、その入口を支援します。

## Concept — 自分の仕事から始める

学生、会社員、フリーランスなど、ユーザーの立場や利用環境に応じて、対話を通じて状況を整理します。必要に応じて利用可能な資料や情報を確認し、外部調査を行い、実行可能なAI活用方法を一緒に考えます。

職業名や所属だけで業務内容を決めつけず、ユーザーが自分のAIワークフローを段階的に育てられることを目指します。

## How It Works

**Understand → Research → Plan → Execute → Verify**

1. **Understand｜理解** — 職業、所属、役割、日常の作業、使用環境を確認します。
2. **Research｜調査** — 必要に応じて業務内容、ソフトウェア、AIツールを調べます。
3. **Plan｜計画** — 目的や制約に合う手順を提案します。
4. **Execute｜実行** — 利用中のAIホストが提供する機能を使い、許可された範囲で作業します。
5. **Verify｜確認** — 作業結果や成果物を確認し、次の改善につなげます。

実行可能な操作は、ホストの機能・認証・権限に依存します。

## Architecture

Work Intake は独自のAIモデルやチャットサービスではありません。既存のAI環境に組み込むSkillです。

- **Codex**
- **Claude Code**
- **Gemini CLI**（対応設計・実機検証未確認）

各ホストの利用には、別途インストール、認証、契約などが必要になる場合があります。

## Demo — 開発過程での実機検証

### Demo 01｜AIホストの検出と起動

Windows 環境で **Codex** と **Claude Code** の起動フローを実機テストしました。開始ファイルから利用可能なホストを検出し、ユーザーが選んだホストで対話を始める導入体験を検証しています。

検証中には、ホストの検出成功と実際の起動成功が異なること、Claude Code の認証状態や起動方法によって自動起動・初期メッセージ送信に問題が生じることを確認しました。実機テスト済みは、全機能の安定動作を意味しません。

### Demo 02｜利用者に合わせた導入フロー

Work Intake は、最初から同じ質問票を全員に要求するのではなく、利用可能で許可された文脈や資料を踏まえて、必要な情報を対話で整理する設計です。

例えば、学生なら学校・専攻・課題、会社員なら職種・担当業務・利用ソフトウェアなどを手がかりに、AIを使える場面を調査・検討します。これは**設計上の利用例**であり、すべての職種で実機検証済みという意味ではありません。

### Demo 03｜検証からの改善

開発では、OSの表示言語と会話言語の不一致、ホスト起動とSkill実行の区別、認証エラーの可視化、OS間での修正の回帰リスクが課題になりました。そのため、**共通Skillを維持しながら、macOSとWindowsの配布パッケージを分離**しています。

## Getting Started — macOS

1. `work-intake-0.3.2-macOS.zip` をダウンロードします。
2. ZIPを完全に展開します。
3. 展開したフォルダ内の `[Mac] START.command` を開きます。
4. 画面の案内に従い、利用可能なAIホストを選びます。
5. ホスト側の認証・権限確認が必要な場合は、その案内に従います。

> macOS版は配布パッケージを用意していますが、この記録ではmacOS実機でのエンドツーエンド動作確認は完了していません。環境により追加操作が必要です。
