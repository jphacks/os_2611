# Work Intake

### AIは使っている。でも、自分の仕事にどう活かせばいい？

**Work Intake** は、ユーザーの仕事・学習環境を理解し、普段使っているAIを実際の作業に活かすためのオープンソースSkillです。新しいAIモデルやチャットサービスを提供するのではなく、既存のAIホストを活用します。

## 製品概要

### 背景

AI初心者にとって難しいのは、AIと会話することだけではありません。「自分の仕事のどこにAIを使えるか」「何を準備すればよいか」「どのツールを選べばよいか」を判断することです。職業や学習環境が違えば、適した使い方も異なります。

### 製品説明

Work Intake は、既存のAIホストに組み込むSkillです。ユーザーとの対話や、アクセスが許可された資料・文脈を通じて現在の状況を整理し、必要に応じて外部情報を調べ、具体的な作業につなげます。

**Understand → Research → Plan → Execute → Verify**

1. **Understand｜理解** — 所属、役割、日常業務、学習内容、使用環境を確認する。
2. **Research｜調査** — 必要に応じて仕事の実態、使用ソフトウェア、利用可能なツールを調べる。
3. **Plan｜計画** — 目的と制約に合わせた実行可能な手順を考える。
4. **Execute｜実行** — ユーザーが許可した範囲で、AIホストの機能を使って作業する。
5. **Verify｜確認** — 結果や成果物を確認し、改善や次の作業につなげる。

実際に利用できる操作は、AIホストの機能、認証状態、権限、実行環境によって異なります。

### 特長1｜仕事から始める導入

学生、会社員、フリーランスなど、特定の職種を前提としません。固定の質問票だけで判断せず、本人の状況を対話で確認します。職業名や所属だけから日常業務を決めつけないことを重視しています。

### 特長2｜普段のAI環境を活用

新しいAIサービスへの移行を求めず、**Codex** や **Claude Code** などの既存環境を入口にします。**Gemini CLI** についても対応を想定していますが、現時点では実機検証を確認できていません。各ホストの利用には別途インストール・ログイン・契約が必要な場合があります。

### 特長3｜提案だけで終わらせない

情報整理やツール提案に加え、ホストが実行可能な範囲でファイル操作や成果物確認までつなげることを目指します。インストール、外部サービスとの連携、重要な変更などには必要な許可を求めます。

### 解決出来ること

- 自分の仕事や学習にAIをどう取り入れるか分からない、という最初の障壁を下げる。
- 作業環境や目的に応じて、AIで試せる具体的な作業を見つける。
- 利用可能なAIホストから、実行と成果物の確認へ段階的に進む。

### 今後の展望

macOS版の実機検証、各AIホストでの起動・認証・Skill実行の安定化、職種ごとの調査精度向上、実際の作業例の拡充を進めます。ユーザーが使いながら自分のワークフローを育てられることを目指します。

### 注力したこと

**Skillの内容、インストール、ホスト起動、実際の対話開始を別々の段階として扱うこと**です。開発中の実機テストを通じて、AIホストを検出できても起動や初期メッセージの送信が成功するとは限らないことが分かりました。また、一方のOS向けの修正が他方に影響しないよう、WindowsとmacOSの配布パッケージを分離しました。

## 開発技術

### 活用した技術

- **AIホスト：** Codex、Claude Code。Gemini CLIは対応設計の対象。
- **Skill：** `SKILL.md` を中心とする、ホストに渡す作業方針・導入フロー。
- **Windows：** バッチファイル（`.cmd`）と PowerShell（`.ps1`）による起動・導入処理。
- **macOS：** シェルスクリプト（`.command` / `.sh`）による起動・導入処理。

### API・データ

Work Intake自体は独自のAIモデルAPIを提供しません。外部調査やファイルへのアクセスは、利用するAIホストが実際に提供する機能と、ユーザーの許可に依存します。固定の業務データセットを前提としない設計です。

### フレームワーク・ライブラリ

今回配布するプラットフォーム別パッケージの起動部分は、Windows標準のバッチ・PowerShell、macOSのシェルスクリプトを中心に構成されています。依存ライブラリの網羅的な一覧は、リポジトリ内の実装・依存関係ファイルを参照してください。

### デバイス

- **Windows PC：** Windows v0.3.3の実機テストを実施。
- **Mac：** macOS v0.3.2の配布パッケージを用意。実機での一連の動作確認は未完了。

## 独自技術

### ハッカソンで開発した独自機能

1. **利用環境に応じたAI導入フロー：** 会話と許可された情報から、必要な質問・調査・作業を組み立てるSkill。
2. **既存AIホストへの導入・起動：** OS別の起動スクリプトを通じて、利用可能なホストへの接続を支援。
3. **OS別パッケージ管理：** WindowsとmacOSを独立して更新し、片方の修正による回帰を減らす構成。

## Getting Started｜使い方

### Windows（v0.3.3・実機テスト済み）

1. `work-intake-0.3.3-Windows.zip` をダウンロードします。
2. `[Windows] START.cmd` を実行します。パッケージ内の案内によると、ZIP内から実行した場合も展開して起動する設計です。**うまく動かない場合は、ZIPを完全に展開してから実行してください。**
3. 画面の案内に従ってAIホストを選びます。
4. 必要な場合は、AIホストでログインや権限確認を行います。
5. Work Intakeとの対話を開始します。

**実機検証：** Windows v0.3.3について、担当メンバーがCodexとClaude Codeで正常動作を確認しました。すべてのPC構成・認証状態での動作を保証するものではありません。

### macOS（v0.3.2・実機検証中）

1. `work-intake-0.3.2-macOS.zip` をダウンロードします。
2. ZIPを**完全に展開**します。
3. 展開したフォルダ内の `[Mac] START.command` をダブルクリックします。
4. 画面の案内に従ってAIホストを選びます。
5. 必要な場合は、AIホストでログインや権限確認を行います。

**検証状況：** 配布パッケージの作成と静的な確認は実施していますが、macOS実機での一連の動作確認は完了していません。
